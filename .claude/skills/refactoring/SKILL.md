# 리팩터링 (Refactoring, 2nd ed.)

리팩터링 = **겉보기 동작은 그대로 두고** 내부 구조를 이해·수정하기 쉽게 바꾸는 것.
작은 단계를 연달아 적용하고, 매 단계 뒤에 테스트를 돌린다. 며칠씩 깨진 채로 두는 건 리팩터링이 아니다.

## 지켜야 할 원칙

1. **두 개의 모자** — 리팩터링 모자와 기능 추가 모자를 동시에 쓰지 않는다. 사용자가 "고치면서 기능도 넣어 달라"고 하면 순서를 나눠서(리팩터링 → 커밋 → 기능) 진행하고 그렇게 한다고 말한다.
2. **테스트가 먼저** — 테스트가 없으면 리팩터링 대상 코드의 현재 동작을 고정하는 테스트부터 만든다(특성화 테스트). 테스트를 일부러 깨뜨려 정말 잡아내는지 한 번 확인한다.
3. **작은 단계, 매번 테스트** — 카탈로그의 절차(mechanics)를 따르고, 단계마다 테스트/타입체크/린트를 돌린다. 실패하면 되돌리고 더 작게 쪼갠다.
4. **삼진 규칙** — 비슷한 코드가 세 번째 나타날 때 정리한다. 두 번째는 참는다.
5. **YAGNI** — 미래를 위한 유연성(불필요한 매개변수·추상화·훅)을 넣지 않는다. 추측성 일반화는 제거 대상이지 추가 대상이 아니다.
6. **성능은 나중에** — 명확한 구조를 먼저 만들고, 느려지면 프로파일러로 측정해 핫스팟만 최적화한다. "느려질까 봐" 리팩터링을 미루지 않는다.
7. **이름이 최우선** — 함수·변수 이름은 "어떻게"가 아니라 "무엇을/왜"를 말해야 한다. 좋은 이름이 안 떠오르면 추출하지 않는다(설계 문제 신호).
8. **도구를 쓴다** — IDE/언어 서버의 rename·extract 같은 안전한 리팩터링이 있으면 텍스트 치환 대신 그것을 쓴다.

## 작업 절차

```
0. 범위 확인  : 무엇을 왜 리팩터링하는지(준비/이해/쓰레기 줍기/계획) 한 줄로 정한다. 사용자가 범위를 안 정했으면 지금 손대는 코드 근처로 제한한다.
1. 안전망     : 테스트 실행 → 초록 확인. 없으면 만든다. 테스트 명령을 기억해 둔다.
2. 악취 진단  : references/smells.md 의 24개 악취 중 해당하는 것을 고른다(1~3개).
3. 기법 선택  : 악취별 처방(아래 표) → references/catalog-*.md 에서 절차를 읽는다.
4. 한 단계 수행 → 테스트 → (선택) 커밋. 반복.
5. 마무리     : 죽은 코드·불필요해진 주석 제거, 이름 재검토, 전체 테스트.
6. 보고       : 아래 "보고 형식".
```

리팩터링 도중 버그를 발견하면 **고치지 말고 기록**한다(다른 모자). 사용자에게 알리고 리팩터링을 끝낸 뒤 별도로 다룬다.

## 악취 → 기법 빠른 참조 (부록 B)

| 악취 | 먼저 시도할 기법 → 그다음 |
|---|---|
| 기이한 이름 | 함수 선언 바꾸기, 변수 이름 바꾸기, 필드 이름 바꾸기 |
| 중복 코드 | 함수 추출하기 → 문장 슬라이드하기, 메서드 올리기 |
| 긴 함수 | 함수 추출하기 → 임시 변수를 질의 함수로, 매개변수 객체, 객체 통째로 넘기기, 조건문 분해, 반복문 쪼개기, 다형성, (최후) 함수를 명령으로 |
| 긴 매개변수 목록 | 매개변수를 질의 함수로, 객체 통째로 넘기기, 매개변수 객체, 플래그 인수 제거, 여러 함수를 클래스로 |
| 전역 데이터 | 변수 캡슐화하기 |
| 가변 데이터 | 변수 캡슐화 → 변수 쪼개기, 질의/변경 분리, 세터 제거, 파생 변수를 질의로, 참조를 값으로 |
| 뒤엉킨 변경 | 단계 쪼개기, 함수 옮기기, 함수 추출, 클래스 추출 |
| 산탄총 수술 | 함수·필드 옮기기, 여러 함수를 클래스/변환 함수로, 단계 쪼개기, (일단 모으려면) 함수·클래스 인라인 |
| 기능 편애 | 함수 옮기기 (일부만이면 먼저 함수 추출) |
| 데이터 뭉치 | 클래스 추출 → 매개변수 객체, 객체 통째로 넘기기 |
| 기본형 집착 | 기본형을 객체로 → 타입 코드를 서브클래스로 + 다형성, 클래스 추출, 매개변수 객체 |
| 반복되는 switch문 | 조건부 로직을 다형성으로 |
| 반복문 | 반복문을 파이프라인으로 |
| 성의 없는 요소 | 함수 인라인, 클래스 인라인, 계층 합치기 |
| 추측성 일반화 | 계층 합치기, 함수·클래스 인라인, 함수 선언 바꾸기(매개변수 제거), 죽은 코드 제거 |
| 임시 필드 | 클래스 추출, 함수 옮기기, 특이 케이스 추가 |
| 메시지 체인 | 위임 숨기기 / 함수 추출 + 함수 옮기기 |
| 중개자 | 중개자 제거, 함수 인라인, 슈퍼/서브클래스를 위임으로 |
| 내부자 거래 | 함수·필드 옮기기, 위임 숨기기, 서브/슈퍼클래스를 위임으로 |
| 거대한 클래스 | 클래스 추출, 슈퍼클래스 추출, 타입 코드를 서브클래스로 |
| 다른 인터페이스의 대안 클래스들 | 함수 선언 바꾸기, 함수 옮기기, 슈퍼클래스 추출 |
| 데이터 클래스 | 레코드 캡슐화, 세터 제거, 함수 옮기기·추출 (예외: 단계 쪼개기의 중간 결과) |
| 상속 포기 | 메서드·필드 내리기; 인터페이스를 거부하면 서브/슈퍼클래스를 위임으로 |
| 주석 | 함수 추출, 함수 선언 바꾸기, 어서션 추가 |

## 하지 말 것

- 리팩터링 커밋에 동작 변경(버그 수정, 기능 추가, 출력 형식 변경) 섞기
- 테스트 없이 여러 파일에 걸친 큰 재구성 한 번에 하기
- 죽은 코드를 주석 처리로 남기기 (버전 관리가 기억한다 — 지운다)
- "나중에 쓸지도 몰라서" 매개변수·추상 클래스·인터페이스 추가하기
- 텍스트 검색·치환으로 이름 바꾸기 (AST 기반 도구 또는 참조를 하나씩 확인)
- 단순한 조건문까지 다형성으로 바꾸기, 짧은 메시지 체인까지 숨기기 — 악취는 "살펴보라"는 신호이지 "무조건 고쳐라"가 아니다
- 사용자가 요청하지 않은 영역까지 정리 범위를 넓히기 (쓰레기 줍기는 지금 지나가는 길에서만)

## 보고 형식

리팩터링을 마치면 다음을 간단히 알린다.
- **발견한 악취**와 위치
- **적용한 기법**(한국어 이름 + English) 과 순서
- **겉보기 동작 변경 없음**을 어떻게 확인했는지 (테스트 명령과 결과)
- 리팩터링 중 발견했지만 **손대지 않은 것**(버그 의심, 다음 리팩터링 후보)
