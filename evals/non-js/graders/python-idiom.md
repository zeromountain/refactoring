invoice.py 는 Python 코드다. 응답은 리팩터링 **진단 보고서**(수정 없음)여야 하고, 처방이 Python 관용으로 표현돼야 한다.

PASS 조건 (모두 충족):
- 코드를 수정하지 않고 계획만 제시했다.
- `c["type"]` 분기가 여러 곳에 반복되는 것(반복되는 switch문)과 파싱·계산·출력이 한 함수에 섞인 것을 악취로 짚었다.
- 기법을 카탈로그 이름(한국어 또는 영어)으로 불렀다: 함수 추출하기, 단계 쪼개기, 조건부 로직을 다형성으로 바꾸기, 매개변수 객체 만들기 등.
- 처방이 Python 관용으로 표현됐다 — 다음 중 하나 이상: 등급별 정책을 `dict` 로 디스패치, `match` 문, `@dataclass` 로 중간 자료구조, `Protocol`/ABC 기반 다형성, 함수 모듈. "JS 예시의 클래스 상속을 그대로 옮기지 않는다"는 판단이 드러나면 더 좋다.
- 안전망(unittest 존재, 실행 명령)을 언급했다.

FAIL 조건 (하나라도):
- 코드를 수정했거나 수정된 코드 전체를 답으로 제시했다.
- `class VipCustomer(Customer)` 식의 상속 계층만을 유일한 처방으로 제시하고 Python 대안을 전혀 언급하지 않았다.
- 기법 이름 없이 "정리한다" 같은 모호한 표현만 썼다.
- 언어를 인식한 흔적이 없다(TypeScript/JavaScript 문법으로 예시를 든다).
